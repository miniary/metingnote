# 04. 작업 계획

MVP 는 3개 Phase 로 진행한다. **Phase 이름과 개수는 아래 3개 그대로 고정이다. 바꾸지 않는다.**

| Phase | 이름 | 범위 | 단계 수 |
|---|---|---|---|
| 1 | 설계 | `CLAUDE.md` + `docs/` 6종 작성 | 10 |
| 2 | 백엔드 | `backend/` FastAPI > API 7개 + 받아쓰기 | 10 |
| 3 | 프론트 | `frontend/` HTML + JS + Tailwind > 화면 4종 > API 연결 | 8 |

## 진행 규칙

- **순서대로만** 한다. 앞 단계가 끝나야 다음 단계로 간다
- **병렬 금지.** 두 단계를 동시에 진행하지 않는다
- **단계별 검증 필수.** 「검증 방법」을 실제로 해 보고 통과해야 완료 칸을 `[x]` 로 바꾼다
- 명령어 약속
  - `backend 진행해` = Phase 2 전체
  - `frontend 진행해` = Phase 3 전체

## Phase 2 - 백엔드

- **서버 포트는 `8000` 으로 고정한다.** (`uvicorn ... --port 8000`)
- **의존성은 아래 8개로 한정한다.** 이 목록 밖은 추가하지 않는다
  - `fastapi` · `uvicorn` · `sqlalchemy` · `pytest` · `httpx` · `google-genai` · `python-multipart` · `python-dotenv`
- pytest 실행 때 `httpx2` 설치 권고가 떠도 무시한다

| 단계 | 검증 방법 | 완료 |
|---|---|---|
| 2.1 `backend/` 뼈대 · 가상환경 · 의존성 8개 설치 | `pip list` 에 8개가 있고 그 밖의 직접 의존성이 없다 | [ ] |
| 2.2 설정 - `.env` 에서 키 · 모델 읽기, 포트 8000 으로 실행 | `uvicorn` 이 8000 에서 뜨고 키가 없으면 알아보기 쉬운 오류를 낸다 | [ ] |
| 2.3 `Meeting` 모델 8필드 · SQLite 테이블 | 테이블 정의에 `AUTOINCREMENT` 가 있고, 지운 id 가 다시 쓰이지 않는다 (pytest) | [ ] |
| 2.4 요청 스키마(`extra=forbid`) · 400 예외 핸들러 | 필수 필드가 없으면 400, 스펙 외 필드는 422 (pytest) | [ ] |
| 2.5 `POST /api/notes` · `GET /api/notes` · `GET /api/notes/{id}` | 201 · 200 · 200, 목록엔 `body` 없음 · 단건엔 있음, 없는 id 404 (pytest) | [ ] |
| 2.6 `PUT /api/notes/{id}` · `DELETE /api/notes/{id}` | 200 · 204, 없는 id 404 (pytest) | [ ] |
| 2.7 검색 - `q` · `from` · `to` | 제목 · 참석자 부분 일치, 본문은 안 찾음, 날짜 양끝 포함 (pytest) | [ ] |
| 2.8 세 갈래 구분 (Gemini) | 프롬프트에 구분 기준이 그대로 있다. 20자 미만 · 실패 시 세 칸 빈 값으로 201, 429 · 503 은 1번 재시도 (pytest, 실제 Gemini 호출 · 호출 사이 1초) | [ ] |
| 2.9 `GET /api/todos` | 응답 필드 `what` · `who` · `when` · `note_id` · `note_title`, 회의 날짜 오래된 순 (pytest) | [ ] |
| 2.10 `POST /api/upload` 받아쓰기 | mp3 · wav 외 415, 25MB 초과 413, 외부 실패 502 (pytest) + 실제 녹취 파일 하나로 본문이 돌아온다 | [ ] |

## Phase 3 - 프론트

- 화면 4종은 `02-specs.md` 화면 명세와 `03-design.md` 표대로 만든다
- 파일은 `frontend/index.html` · `frontend/app.js` 2개만 둔다

| 단계 | 검증 방법 | 완료 |
|---|---|---|
| 3.1 `index.html` · `app.js` 뼈대, 백엔드가 같은 오리진에서 제공 | `http://localhost:8000` 에서 화면이 뜬다 (`file://` 로 열지 않음). 헤더 · 탭 3개 · 테마 버튼이 있다 | [ ] |
| 3.2 테마 토글 | 초기값이 시스템 설정을 따르고, 바꾼 값이 새로고침 뒤에도 `localStorage` 로 유지된다 | [ ] |
| 3.3 목록 화면 | 카드 2열 (360px 에서 1열), 입력할 때마다 검색이 다시 불린다 | [ ] |
| 3.4 넣기 화면 | 받아쓰기로 본문이 채워지고, 정리하기로 세 칸이 표시된다. `met_at` 을 UTC 로 바꿔 보낸다 | [ ] |
| 3.5 상세 화면 | 카드를 누르면 겹침 창이 뜨고, 바깥을 누르면 닫힌다. 제목 수정(PUT) · 삭제는 두 번 눌러야 지워진다(DELETE) | [ ] |
| 3.6 할 일 화면 | 표로 보이고, 좁은 화면에서는 표만 가로 스크롤된다 (문서 전체 가로 스크롤 없음) | [ ] |
| 3.7 요소 이름 확인 | `index.html` 의 id 가 `03-design.md` 요소 이름 표와 하나도 빠짐없이 같다 | [ ] |
| 3.8 API 연결 · 성공 기준 확인 | `01-product.md` 성공 기준 4개를 화면에서 눈으로 확인한다 (세 갈래 저장 · 새로고침 유지 · 360px · 검색) | [ ] |
